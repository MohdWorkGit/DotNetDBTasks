API reference

Every endpoint the API exposes, grouped by area, with the permission each one needs. The running API also describes itself at /swagger.

للمطورين

مرجع API

كل نقطة وصول يتيحها الـAPI، مجمّعة حسب المجال، مع الصلاحية التي تحتاجها كل واحدة. ويصف الـAPI نفسه أيضًا أثناء التشغيل على /swagger.

How to read it

  • Sign-in. Everything uses a JWT bearer token unless marked otherwise: Authorization: Bearer <accessToken> from POST /api/auth/login.
  • Permission. Endpoints name a permission, not a role. a | b means either one is enough; two badges mean both are needed. signed in means any valid token; anonymous means no token at all.
  • Notes are in English on both language versions of this page, since they quote code.

Some rules live in the handlers and no route list can show them:

  • A role without queries.run never gains query access, however a query is granted to it.
  • Exporting needs two grants: the query's (or report's) allowed formats, and the matching *.export* permission.
  • Reports and dashboards never widen access: each query inside is checked as if run directly. A dashboard tile the caller cannot run answers 200 with its error set, not 403.
  • Tile results are shared between viewers per tile and per set of filter values for the tile's interval; only real runs are logged.
  • A non-Admin cannot touch an administrator account, grant Admin, change their own roles, or join a user group.
  • The directory.enabled setting switches the whole /api/admin/ldap area off (503).

كيف تقرأ هذه الصفحة

  • تسجيل الدخول. كل شيء يستخدم رمز JWT ما لم يُذكر غير ذلك: Authorization: Bearer <accessToken> من POST /api/auth/login.
  • الصلاحية. نقاط الوصول تطلب صلاحية لا دورًا. a | b تعني أن إحداهما تكفي، وشارتان تعنيان أن الاثنتين مطلوبتان. signed in تعني أي رمز صالح، وanonymous تعني بلا رمز إطلاقًا.
  • الملاحظات بالإنجليزية في النسختين، لأنها تقتبس من الشيفرة.

بعض القواعد في معالجات الأوامر، ولا تظهر في أي قائمة مسارات:

  • الدور الذي لا يحمل queries.run لا يكتسب وصولًا إلى أي استعلام، مهما مُنح له.
  • التصدير يحتاج منحين: الصيغ المسموحة في الاستعلام (أو التقرير)، وصلاحية *.export* المقابلة.
  • التقارير واللوحات لا توسّع الصلاحيات: كل استعلام فيها يُفحص كأنه شُغّل مباشرة. وبطاقة اللوحة التي لا يستطيع الطالب تشغيلها تجيب بـ200 مع حقل error، لا بـ403.
  • نتائج البطاقات مشتركة بين المشاهدين لكل بطاقة ولكل مجموعة قيم مرشحات طوال مدة تحديثها؛ ولا يُسجَّل إلا التشغيل الفعلي.
  • غير المسؤول لا يستطيع المساس بحساب مسؤول، ولا منح الدور Admin، ولا تغيير أدواره، ولا الانضمام إلى مجموعة مستخدمين.
  • الإعداد directory.enabled يوقف مجال /api/admin/ldap كله (503).

Signing in

تسجيل الدخول

/api/auth · 4 endpointsنقطة وصول

VerbالطريقةPathالمسارPermissionالصلاحيةNotesملاحظات
GET/api/auth/ssoanonymousWindows SSO (Kerberos/NTLM). 404 unless Auth:EnableSso=true in appsettings. Provisions the account from AD with the User role on first sign-in and re-syncs the profile on each one. The sign-in page calls this by itself on load, so a domain user never reaches the form; the 404 and 401 paths are the silent fallback to it. Requires withCredentials — the browser will not perform the handshake otherwise.
POST/api/auth/loginanonymousUsername and password. Handles both local accounts (BCrypt hash) and directory accounts (LDAP bind) — the account's AuthSource decides which. Rate limited per client IP (Auth:Login:PermitLimit, default 10 per 60s); 429 when exceeded.
POST/api/auth/refreshanonymousExchanges a valid refresh token for a new access token. Body carries the expired access token and the refresh token.
GET/api/auth/mesigned in{ username, roles, permissions }: the signed-in account and the permissions its roles add up to, read fresh. The client calls it to decide which menus to show.

No class-level [Authorize]; all three are anonymous.

Both login and refresh return { accessToken, refreshToken, expiresAt, username, roles }. expiresAt is the access token's own expiry — the lifetime comes from the session.accessTokenMinutes setting, not from a constant.

The tab icon is independent of that chain: it is a square uploaded on its own rather than the logo scaled down, and its absence means the browser's default, not a fallback of ours. Both images live in SystemTemplates under branding-logo and branding-favicon.

Class: [RequirePermission] with queries.run, reports.run or dashboards.run — any one is enough to reach the controller, because the report viewer and the dashboard rows dialog page their cached rows through GET /jobs/{jobId}/rows. Every action that touches a query restates queries.run itself, so the other two reach only their own cached rows. Ownership of a job is checked in code — the submitting user or an Admin, otherwise 403.

410 Gone, and why it is not 404. The job store is in-memory, so a job id stops resolving once the result expires on its retention window, is released, or the worker process restarts under it. All three are "it was here and now it isn't", not "no such thing" — the body carries { message } saying the result is no longer available and to run the query again, which the client shows verbatim. Treat it as a terminal state for a poll loop: retrying the same id will never succeed.

The whole controller needs queries.run, and the list returns only what the caller has been granted. No seeded role but User and Admin holds it, which is why the client hides My Queries and History from the others — but it is a permission like any other, and can be granted.

KPI rule. With kpiAggregate Last (the default) a KPI tile reads its rows as a series in query order: the headline is the last row's value column, the comparison is the compare column on that row or — without one — the row before it, and every row draws the sparkline. SELECT month, total ... ORDER BY month therefore shows this month against last month with no further setup. Sum, Average, Min and Max summarise the value column over every row (non-numbers skipped) and the compare column the same way; Count is the number of rows. With a targetValue, kpi.targetStatus is met, near (within targetWarnPercent of the target on the wrong side) or missed, judged in the direction higherIsBetter gives.

Date presets. Wherever a date filter takes a value — its default, the tile data body, the URL, a scheduled item — it also accepts today, today-N, today+N, week_start (Sunday), month_start, month_end, last_month_start, last_month_end and year_start. The token is kept as-is and resolved in the server's local time when a query runs, so a bookmarked link, a wall screen or a nightly snapshot keeps meaning "this month". The shared tile cache is keyed on the resolved date, so it rolls over by itself.

POST/api/admin/transfer/importsigned inImports a file written by any export endpoint, including a format-1 query backup. multipart file, ≤50 MB. Needs queries.transfer, reports.transfer and/or dashboards.transfer for each kind the file holds — all checked before anything is written (403 naming the missing one). Dashboard items. An item runs exactly one of dynamicQueryId, reportId or dashboardId (400 otherwise). A dashboard item runs every tile fresh as the task's creator — through the same access checks, parameter routing, date presets and KPI rules as the live page, bypassing the shared cache — and writes one document: a chart and its figures per chart tile, a row of figures per KPI, the rows of a table tile, with the filter values in the header. parameters holds the dashboard's filter values by filter name; empty ones take the filter's default. Only PDF, Word and Excel (one sheet per tile) are accepted, and it cannot be incremental. A tile the creator cannot run is listed in the item's error while the run still succeeds; if every tile fails the item fails.
