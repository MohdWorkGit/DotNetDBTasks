Security and permissions

How people sign in, what decides what they can reach, the rules no setting can switch off, and the records kept of what everyone did.

باختصار

Sign-inتسجيل الدخول

Active Directory or LDAP password, or local accounts. Windows sign-in with no form on IIS (off by default). JWT access and refresh tokens. Login is rate-limited per address.

كلمة مرور Active Directory أو LDAP، أو حسابات محلية. ودخول تلقائي بحساب Windows دون نموذج على IIS (متوقف افتراضيًا). رموز JWT للوصول والتجديد. ومحاولات الدخول محدودة لكل عنوان.

Permissionsالصلاحيات

44 permissions, held by roles you can edit and add to. Checked on every request, not read from the token.

44 صلاحية، تحملها أدوار يمكنك تعديلها وإضافة غيرها. تُفحص مع كل طلب، ولا تُقرأ من الرمز.

Dataالبيانات

Values always bound, never pasted into SQL. Database passwords encrypted with AES-256. Changes previewed before they commit.

القيم تُمرَّر دائمًا ولا تُلصق في نص SQL. كلمات مرور قواعد البيانات مشفّرة بـAES-256. والتعديلات تُعاين قبل اعتمادها.

Recordsالسجلات

Every run in the execution log, every change in the system audit trail, refusals included.

كل تشغيل في سجل التنفيذ، وكل تغيير في سجل عمليات النظام، بما فيها المحاولات المرفوضة.

Roles and the permission matrix

Each endpoint names a permission, not a role. A role is a named set of permissions, edited at Settings → Roles and permissions. Four roles come built in and you can add more. A person may hold several roles; their permissions add up.

The matrix below is what each built-in role holds on a fresh install. Admin holds everything, always.

الأدوار وجدول الصلاحيات

كل نقطة وصول تطلب صلاحية لا دورًا. والدور مجموعة صلاحيات لها اسم، تُعدَّل في الإعدادات ← الأدوار والصلاحيات. أربعة أدوار مدمجة، ويمكنك إضافة غيرها. وقد يحمل الشخص عدة أدوار، فتجتمع صلاحياتها.

الجدول أدناه هو ما يحمله كل دور مدمج في التثبيت الجديد. والدور Admin يحمل كل شيء دائمًا.

The permission names are stored in the database, so renaming one silently takes it away from everyone. Adding one is safe: nobody holds it until someone ticks the box, so a new permission starts closed.

Accounts seeded for development, to change or remove before going live: admin / Admin@123, user / User@123, auditor / Auditor@123, accessmanager / Access@123.

أسماء الصلاحيات محفوظة في قاعدة البيانات، فتغيير اسم صلاحية يسحبها من الجميع دون تنبيه. أما إضافة صلاحية جديدة فآمنة: لا يحملها أحد حتى يعلّمها أحد، فتبدأ مغلقة.

حسابات مُنشأة للتطوير، يجب تغييرها أو حذفها قبل التشغيل الفعلي: admin / Admin@123، وuser / User@123، وauditor / Auditor@123، وaccessmanager / Access@123.

Rules that hold whatever the matrix says

  • Admin is pinned. It holds every permission, its column cannot be edited, and it cannot be deleted. Otherwise the last account able to open the permissions page could be edited out of it.
  • Built-in roles keep their names. Their permissions can be edited, but they cannot be renamed or deleted.
  • A role in use cannot be deleted. Move its people first.
  • Nobody grants themselves. A non-Admin cannot change their own roles, grant Admin, touch an administrator's account, or add themselves to a user group.
  • Changes apply on the next click. Permissions and group membership are checked on every request, so nobody has to sign out for a removal to work.
  • A query granted to a role that cannot run queries does nothing. A role without queries.run never gains access through a query grant.
  • Reports and dashboards never widen access. Each query inside them is checked as if the person ran it directly.

قواعد ثابتة مهما كان جدول الصلاحيات

  • الدور Admin مثبَّت. يحمل كل صلاحية، ولا يمكن تعديل عموده ولا حذفه. وإلا لأمكن إخراج آخر حساب يستطيع فتح صفحة الصلاحيات منها.
  • الأدوار المدمجة تحتفظ بأسمائها. يمكن تعديل صلاحياتها، لكن لا يمكن تغيير أسمائها أو حذفها.
  • الدور المستخدَم لا يُحذف. انقل أصحابه إلى دور آخر أولًا.
  • لا أحد يمنح نفسه. غير المسؤول لا يستطيع تغيير أدواره، ولا منح الدور Admin، ولا المساس بحساب مسؤول، ولا إضافة نفسه إلى مجموعة مستخدمين.
  • التغييرات تسري من النقرة التالية. الصلاحيات وعضوية المجموعات تُفحص مع كل طلب، فلا حاجة لتسجيل الخروج حتى تسري الإزالة.
  • منح استعلام لدور لا يستطيع تشغيل الاستعلامات لا أثر له. الدور الذي لا يحمل queries.run لا يكتسب وصولًا من منح استعلام.
  • التقارير واللوحات لا توسّع الصلاحيات أبدًا. كل استعلام فيها يُفحص كأن الشخص شغّله بنفسه.

What a saved query may contain

Every query is checked when it is saved:

  • -- and ; are refused anywhere: one statement per query, no comments that could hide the rest of a line.
  • Names starting with XP_, SP_, DBMS_ or UTL_ are refused (only at the start of a name, so REGEXP_REPLACE is fine).
  • The text is limited to query.sqlMaxLength characters (4,000 by default).
  • Validation runs on every input, and every query has a timeout (or none, if set to unlimited).

SQL written by the AI assistant passes a stricter check first, described on the AI page. The strongest protection of all does not depend on Jadwal: give connections database accounts that can only read, wherever writing is not needed.

ما يجوز أن يحتويه الاستعلام المحفوظ

يُفحص كل استعلام عند حفظه:

  • -- و; مرفوضتان في أي مكان: جملة واحدة لكل استعلام، ولا تعليقات قد تخفي بقية السطر.
  • الأسماء التي تبدأ بـXP_ أو SP_ أو DBMS_ أو UTL_ مرفوضة (في بداية الاسم فقط، فالدالة REGEXP_REPLACE مقبولة).
  • طول النص محدود بالإعداد query.sqlMaxLength (4,000 حرف افتراضيًا).
  • كل المدخلات يُتحقق منها، ولكل استعلام مهلة تنفيذ (أو بلا حد إن ضُبط كذلك).

ما يكتبه المساعد الذكي من SQL يمر أولًا بفحص أشد، مشروح في صفحة المساعد الذكي. وأقوى حماية لا تعتمد على «جدول» أصلًا: أعطِ الاتصالات حسابات قواعد بيانات للقراءة فقط، حيث لا حاجة للتعديل.

Settings you can change while it runs

Stored in the database and edited at Settings (settings.manage), so they change without a restart. A missing value means the default. Each value is range-checked, and every change is recorded in the audit trail.

The audit trail

Two records answer two questions:

Execution logs: what did people run?

Every run, preview and failure: who, the values, how long, how many rows, the error if any, and for UPDATE and DELETE the rows as they were before. Read with logs.view.

System audit: what did people change?

Every administrative change: a user created, a permission granted, a query edited, an AI request. Read with audit.view.

  • Nothing is left out by accident. Entries are written by one step every command passes through, so a new command is recorded without anyone remembering to.
  • Refusals are recorded too. "The access manager tried to reset the admin's password and was refused" is often the entry that matters.
  • Secrets never reach it. Any field named like a password, secret, token, connection string, key or credential is replaced with ***; file contents become [omitted].
  • Read only. The API has no way to change or delete an entry, except the retention clean-up.
  • Actions are stored as codes (users.create) and translated on screen, so the trail reads in Arabic too.

سجل العمليات

سجلّان يجيبان عن سؤالين:

سجلات التنفيذ: ماذا شغّل الناس؟

كل تشغيل ومعاينة وفشل: مَن، والقيم، والمدة، وعدد الصفوف، والخطأ إن وجد، وفي UPDATE وDELETE الصفوف كما كانت قبل التغيير. تُقرأ بصلاحية logs.view.

سجل عمليات النظام: ماذا غيّر الناس؟

كل تغيير إداري: إنشاء مستخدم، أو منح صلاحية، أو تعديل استعلام، أو طلب من الذكاء الاصطناعي. يُقرأ بصلاحية audit.view.

  • لا شيء يُنسى سهوًا. القيود تكتبها خطوة واحدة يمر بها كل أمر، فيُسجَّل أي أمر جديد دون أن يتذكره أحد.
  • المحاولات المرفوضة تُسجَّل أيضًا. «حاول مدير الوصول إعادة تعيين كلمة مرور المسؤول فرُفض» هو غالبًا القيد الأهم.
  • الأسرار لا تصل إليه أبدًا. أي حقل يشبه اسمه كلمة مرور أو سرًا أو رمزًا أو نص اتصال أو مفتاحًا يُستبدل بـ***، ومحتوى الملفات يصبح [omitted].
  • للقراءة فقط. لا يتيح الـAPI تعديل قيد أو حذفه، إلا التنظيف حسب مدة الحفظ.
  • العمليات تُحفظ رموزًا (users.create) وتُترجم على الشاشة، فيُقرأ السجل بالعربية أيضًا.

Before going live

  • A strong, unique Jwt:Secret (at least 32 random characters).
  • A unique Encryption:Key (32 bytes, base64), kept safe. Lose it and stored database passwords cannot be read.
  • The seeded development accounts changed or removed.
  • Ldap:Host pointing at the right server, tested with a real sign-in.
  • HTTPS: a certificate on the IIS site, or at the reverse proxy.
  • Read-only database accounts for connections that only need to read.
  • Retention set for the two logs, or a plan for their growth; backups of the database.
  • Only the ports you need open in the firewall.

قبل التشغيل الفعلي

  • قيمة قوية وفريدة لـJwt:Secret (32 حرفًا عشوائيًا على الأقل).
  • قيمة فريدة لـEncryption:Key (32 بايت بترميز base64)، محفوظة بأمان. ضياعها يعني عدم القدرة على قراءة كلمات مرور قواعد البيانات المحفوظة.
  • تغيير حسابات التطوير المُنشأة مسبقًا أو حذفها.
  • Ldap:Host يشير إلى الخادم الصحيح، مع تجربة دخول حقيقية.
  • HTTPS: شهادة على موقع IIS، أو عند الوسيط العكسي.
  • حسابات قواعد بيانات للقراءة فقط للاتصالات التي لا تحتاج إلا القراءة.
  • مدة حفظ للسجلين، أو خطة لنموهما؛ ونسخ احتياطي لقاعدة البيانات.
  • فتح المنافذ اللازمة فقط في الجدار الناري.
