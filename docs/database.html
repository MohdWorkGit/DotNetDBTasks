For developers

Database

Jadwal keeps its own data in one database (Oracle in production; SQL Server, PostgreSQL and MySQL also work), through Entity Framework Core. The queries it runs can reach any number of other databases, through the connections an administrator sets up.

قاعدة البيانات

يحفظ «جدول» بياناته في قاعدة بيانات واحدة (Oracle في بيئة التشغيل، وتعمل أيضًا SQL Server وPostgreSQL وMySQL) عبر Entity Framework Core. أما الاستعلامات التي يشغّلها فيمكن أن تصل إلى أي عدد من قواعد البيانات الأخرى، عبر الاتصالات التي يُعدّها المسؤول.

The tables and how they relate

45 tables in eight areas. Saved queries sit in the middle: reports, dashboards and scheduled tasks all read through them, and every one of those is granted to people the same three ways: to a role, a user group, or a named user (for dashboards, the DashboardRoles, DashboardUserGroups and DashboardUsers tables, and likewise for the others).

الجداول والعلاقات بينها

45 جدولًا في ثمانية مجالات. الاستعلامات المحفوظة في المنتصف: التقارير واللوحات والمهام المجدولة كلها تقرأ من خلالها، وكل منها يُمنح للناس بالطرق الثلاث نفسها: لدور، أو لمجموعة مستخدمين، أو لمستخدم باسمه (في اللوحات مثلًا الجداول DashboardRoles وDashboardUserGroups وDashboardUsers، وهكذا في غيرها).

The schema is changed by EF Core migrations in src/Jadwal.Infrastructure/Data/Migrations. The API applies any new ones itself at start-up, before serving a request; there is no separate database step. The folder is the authority; the list below is grouped by month.

Migrations that move data

SwitchAccessFromAdDepartmentsToUserGroups turns each department that granted something into a user group of the same name, fills it with the users whose department matched, re-points the grants, and only then drops the old tables. The inserts must run while the old tables still exist: reordering the create and drop calls would migrate nothing, succeed anyway, and lose every department grant. Its Down() is lossy by nature: a group made in the app has no department to become.

ترحيلات تنقل البيانات

الترحيل SwitchAccessFromAdDepartmentsToUserGroups يحوّل كل قسم كان يمنح شيئًا إلى مجموعة مستخدمين بالاسم نفسه، ويملؤها بالمستخدمين الذين يطابق قسمهم، ويعيد توجيه المنح إليها، ثم يحذف الجداول القديمة بعد ذلك فقط. يجب أن تعمل الإضافات والجداول القديمة ما زالت موجودة: فتغيير ترتيب الإنشاء والحذف لن ينقل شيئًا، وسينجح مع ذلك، وتضيع كل منح الأقسام. ودالة Down() فيه تفقد بعض المعلومات بطبيعتها: فالمجموعة المنشأة في التطبيق ليس لها قسم تعود إليه.

The Oracle rules

Oracle differs from SQL Server and PostgreSQL in ways that broke migrations here before (ORA-00904 "invalid identifier" on a column a half-applied migration never added). Follow these for every migration:

قواعد Oracle

يختلف Oracle عن SQL Server وPostgreSQL في أمور أفسدت ترحيلات هنا من قبل (الخطأ ORA-00904 «معرّف غير صالح» على عمود لم يُضفه ترحيل طُبّق نصفه). اتبع هذه القواعد في كل ترحيل:

1 · Schema changes cannot be undoneتعديلات المخطط لا يُتراجع عنها

Oracle commits every DDL statement at once. A migration that fails half-way stays half-applied and is not recorded, so the next run fails with ORA-01430 ("column already exists") for ever.

يعتمد Oracle كل جملة تعريف فورًا. فالترحيل الذي يفشل في منتصفه يبقى نصف مطبّق ولا يُسجَّل، فيفشل التشغيل التالي بالخطأ ORA-01430 («العمود موجود») إلى الأبد.

2 · Make every step safe to repeatاجعل كل خطوة آمنة للتكرار

Wrap each ADD in PL/SQL that ignores ORA-01430 (and ORA-00955 for objects), so a re-run skips what already exists.

ضع كل ADD داخل PL/SQL يتجاهل ORA-01430 (وORA-00955 للكائنات)، فيتجاوز التشغيل المكرر ما هو موجود.

3 · An empty string is NULLالنص الفارغ هو NULL

Oracle stores '' as NULL. A column that may be empty must be nullable (string?), never NOT NULL DEFAULT ''.

يحفظ Oracle النص '' على أنه NULL. فالعمود الذي قد يكون فارغًا يجب أن يقبل NULL (string?)، لا NOT NULL DEFAULT ''.

4 · All columns in CreateTableكل الأعمدة في CreateTable

Never add columns in a second migration to a table created in the same release; combine them.

لا تُضف أعمدة في ترحيل ثانٍ إلى جدول أُنشئ في الإصدار نفسه؛ اجمعهما.

5 · Fill the Designer.cs filesاملأ ملفات Designer.cs

A hand-written migration needs the model snapshot in its Designer.cs, or later migrations are generated wrong.

الترحيل المكتوب يدويًا يحتاج لقطة النموذج في ملف Designer.cs، وإلا وُلّدت الترحيلات اللاحقة خطأً.

6 · Test on a clean databaseاختبر على قاعدة بيانات نظيفة

After changing any migration, drop everything (including __EFMigrationsHistory) and let the whole chain apply.

بعد تعديل أي ترحيل، احذف كل شيء (ومعه __EFMigrationsHistory) ودع السلسلة كلها تُطبَّق.

-- Rule 2: a column add that is safe to run again
BEGIN
    EXECUTE IMMEDIATE 'ALTER TABLE "MyTable" ADD "MyCol" NUMBER(10)';
EXCEPTION
    WHEN OTHERS THEN
        IF SQLCODE != -1430 THEN RAISE; END IF;
END;

Names and booleans

  • Quote names. Oracle turns unquoted names into capitals, and Jadwal's tables use quoted PascalCase: SELECT "Username" FROM "Users" works, SELECT Username FROM Users fails with ORA-00904. Saved queries are best written with [brackets], which Jadwal converts to each database's quoting.
  • Booleans are NUMBER(1). Filtering one inside a LINQ Where on Oracle can throw a cast error; read the rows and filter in memory where that happens.
  • Long numbers. An Oracle NUMBER wider than .NET's decimal (an unrounded AVG, say) is read safely; round it in SQL if the full precision is not wanted.
  • Never set Database:AllowDestructiveRepair on a database whose data matters: its repair drops every table and starts again.

الأسماء والقيم المنطقية

  • ضع الأسماء بين علامات تنصيص. يحوّل Oracle الأسماء غير المنصّصة إلى أحرف كبيرة، وجداول «جدول» بأسماء منصّصة: SELECT "Username" FROM "Users" يعمل، وSELECT Username FROM Users يفشل بالخطأ ORA-00904. والأفضل كتابة الاستعلامات المحفوظة بالأقواس [brackets]، التي يحوّلها «جدول» إلى طريقة كل قاعدة بيانات.
  • القيم المنطقية NUMBER(1). تصفيتها داخل Where في LINQ على Oracle قد ترمي خطأ تحويل؛ فاقرأ الصفوف وصفِّها في الذاكرة حيث يحدث ذلك.
  • الأرقام الطويلة. رقم Oracle الأطول من decimal في .NET (مثل AVG غير مقرّب) يُقرأ بأمان؛ وقرّبه في SQL إن لم تكن الدقة الكاملة مطلوبة.
  • لا تضبط Database:AllowDestructiveRepair أبدًا على قاعدة بيانات تهمّك بياناتها: «إصلاحه» يحذف كل الجداول ويبدأ من جديد.
