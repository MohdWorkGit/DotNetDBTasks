Deployment

Jadwal can run in Docker on a connected network, or on a server with no internet at all. For the offline case everything is built on a connected machine and carried across.

Docker (internet-connected)

Needs Docker with Compose and about 4 GB of free memory. The stack starts Oracle XE 21c, OpenLDAP, the API and the Angular client behind nginx.

A stack first started under the old name, Bayan

An offline release with nginx

Build on a connected machine; the server only needs to run Jadwal. (For IIS, which most Windows servers should use, see IIS hosting; the build and the settings below are the same.)

The fast way: ./scripts/prepare-offline-bundle.ps1 -Clean -IncludeBuild -IncludeInstallers builds everything below into one offline-bundle/ folder with a MANIFEST.txt to follow. It also carries this documentation and the Word user manuals in its docs folder.

نشر دون إنترنت مع nginx

ابنِ على جهاز متصل؛ فالخادم لا يحتاج إلا تشغيل «جدول». (أما IIS، وهو ما يناسب أغلب خوادم Windows، ففي الاستضافة على IIS؛ والبناء والإعدادات أدناه هي نفسها.)

الطريقة السريعة: الأمر ./scripts/prepare-offline-bundle.ps1 -Clean -IncludeBuild -IncludeInstallers يبني كل ما يلي في مجلد واحد offline-bundle/ مع ملف MANIFEST.txt تتبعه. ويحمل أيضًا هذا التوثيق ودليلي المستخدم بصيغة Word في مجلد docs.

1 · Build

١ · البناء

# API, self-contained: the .NET runtime comes with it (use -r linux-x64 for Linux)
dotnet publish src/Jadwal.API/Jadwal.API.csproj -c Release -r win-x64 --self-contained -o ./api-publish

# Optional: the standalone QueryRunner tool
dotnet publish tools/Jadwal.QueryRunner -c Release -r win-x64 --self-contained -o ./queryrunner-publish

# Angular client, from client/  ->  client/dist/jadwal-client/browser/
npm ci
npm run build:prod

The database drivers (Oracle, SQL Server, MySQL, PostgreSQL) are inside the publish output; no database client is installed on the server.

برامج تشغيل قواعد البيانات (Oracle وSQL Server وMySQL وPostgreSQL) داخل مخرجات النشر؛ فلا يُثبَّت أي عميل قاعدة بيانات على الخادم.

{

  "Jwt": { "Secret": "A_LONG_RANDOM_SECRET_OF_AT_LEAST_32_CHARACTERS" },

  "Ldap": {

  },
  "Cors": { "AllowedOrigins": ["http://YOUR_SERVER"] }
}
Keep Encryption:Key the same forever

It encrypts the stored database passwords. Change it between builds and every stored password becomes unreadable.

For Active Directory the default attributes (sAMAccountName, department) are right; just point Ldap:Host at the server. For OpenLDAP use uid / departmentNumber. The department only feeds the Active Directory users page; it does not decide anyone's access.

أبقِ Encryption:Key ثابتًا دائمًا

هو ما يشفّر كلمات مرور قواعد البيانات المحفوظة. غيّره بين نسختين، فتصبح كل كلمة مرور محفوظة غير مقروءة.

مع Active Directory تكون الخصائص الافتراضية (sAMAccountName وdepartment) صحيحة؛ يكفي توجيه Ldap:Host إلى الخادم. ومع OpenLDAP استخدم uid وdepartmentNumber. والقسم لا يغذّي إلا صفحة مستخدمي Active Directory، ولا يحدد صلاحيات أحد.

4 · nginx

The client calls /api on the same address, so nginx serves the files and passes /api to the API. Save as conf/nginx.conf:

٤ · nginx

الواجهة تطلب /api على العنوان نفسه، فيقدّم nginx الملفات ويمرّر /api إلى الـAPI. احفظ الملف باسم conf/nginx.conf:

worker_processes 1;
events { worker_connections 1024; }
http {
    include mime.types;
    default_type application/octet-stream;
    sendfile on;
    keepalive_timeout 65;
    server {
        listen 80;
        root C:/deploy/client;           # where the browser/ folder was copied
        index index.html;
        location / { try_files $uri $uri/ /index.html; }
        location /api {
            proxy_pass http://localhost:5000;
            proxy_http_version 1.1;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
        }
    }
}

5 · On the server

٥ · على الخادم

  1. Install Oracle XE 21c. It listens on localhost:1521/XEPDB1.
  2. Copy the files to C:\deploy\api, C:\deploy\client and C:\deploy\nginx.
  3. Run the API as a Windows service, so scheduled tasks keep running: sc.exe create Jadwal binPath="C:\deploy\api\Jadwal.API.exe" then sc.exe start Jadwal. Its account needs write access to every task's output and archive folder. It listens on port 5000 (change with "Urls" in appsettings.json).
  4. Start nginx: .\nginx.exe in C:\deploy\nginx (-s stop to stop).
  5. Check: the site opens at http://YOUR_SERVER; sign in as an administrator and open Dashboards: the page loading proves the tables exist, a tile with data proves its query runs.

Start order: Oracle first, then the API (it waits for the database), then nginx.

  1. ثبّت Oracle XE 21c. يعمل على localhost:1521/XEPDB1.
  2. انسخ الملفات إلى C:\deploy\api وC:\deploy\client وC:\deploy\nginx.
  3. شغّل الـAPI كخدمة Windows لتستمر المهام المجدولة: sc.exe create Jadwal binPath="C:\deploy\api\Jadwal.API.exe" ثم sc.exe start Jadwal. ويحتاج حسابها صلاحية الكتابة في مجلدات الإخراج والأرشيف لكل مهمة. وتعمل على المنفذ 5000 (يُغيَّر بـ"Urls" في appsettings.json).
  4. شغّل nginx: .\nginx.exe داخل C:\deploy\nginx (و-s stop للإيقاف).
  5. تحقق: يفتح الموقع على http://YOUR_SERVER؛ سجّل الدخول كمسؤول وافتح لوحات المعلومات: تحميل الصفحة يثبت وجود الجداول، وبطاقة فيها بيانات تثبت أن استعلامها يعمل.

ترتيب التشغيل: Oracle أولًا، ثم الـAPI (ينتظر قاعدة البيانات)، ثم nginx.

Upgrading

A new release is carried across the same way. The difference is that the database already exists, and the API changes it itself, on start-up, before serving any request.

Back up the schema first

Oracle cannot undo half a schema change. If an upgrade fails part-way, the API refuses to start (ORA-00955 or ORA-01430 in the log) and the backup is your way back. Never set Database:AllowDestructiveRepair on a database whose data matters: its "repair" drops every table. The schema account must still be able to create tables and indexes. See the Oracle rules.

الترقية

تُنقل النسخة الجديدة بالطريقة نفسها. الفرق أن قاعدة البيانات موجودة أصلًا، والـAPI يعدّلها بنفسه عند التشغيل، قبل أن يخدم أي طلب.

خذ نسخة احتياطية من المخطط أولًا

لا يستطيع Oracle التراجع عن نصف تعديل على المخطط. فإن فشلت الترقية في منتصفها، يرفض الـAPI البدء (ORA-00955 أو ORA-01430 في السجل)، والنسخة الاحتياطية هي طريق العودة. ولا تضبط Database:AllowDestructiveRepair أبدًا على قاعدة بيانات تهمّك بياناتها: «إصلاحه» يحذف كل الجداول. ويجب أن يبقى حساب المخطط قادرًا على إنشاء الجداول والفهارس. انظر قواعد Oracle.

# 1. Back up the schema (Data Pump, RMAN, or your DBA's way)
# 2. Stop the API (the service, or the IIS app pool)
sc.exe stop Jadwal
# 3. Replace the API files, keeping your settings and history
robocopy <bundle>\api-publish C:\deploy\api /E /XF appsettings.json /XD logs cache
# 4. Replace the client files
robocopy <bundle>\client-dist C:\deploy\client /MIR
# 5. Start, and watch the log while the changes apply
sc.exe start Jadwal
Get-Content C:\deploy\api\logs\log-*.txt -Tail 50 -Wait
  • New features arrive switched off for everyone but Admin. A release that adds permissions grants them only to Admin. To let others use, say, dashboards, add the permission to their role and grant the dashboards.
  • A server installed under the old name, Bayan, keeps it. Point the service at the new file once: sc.exe config Bayan binPath="C:\deploy\api\Jadwal.API.exe". Under IIS, upgrade in place with deploy-iis.ps1 -SiteName Bayan -PhysicalPath <the site's folder>; the script refuses to create a second site, which would run every scheduled export twice.
  • الخصائص الجديدة تصل متوقفة للجميع ما عدا Admin. النسخة التي تضيف صلاحيات لا تمنحها إلا للدور Admin. ولتتيح لغيره لوحات المعلومات مثلًا، أضف الصلاحية إلى دوره وامنحه اللوحات.
  • الخادم المثبَّت بالاسم القديم Bayan يحتفظ به. وجّه الخدمة إلى الملف الجديد مرة واحدة: sc.exe config Bayan binPath="C:\deploy\api\Jadwal.API.exe". وعلى IIS رقِّ في المكان نفسه بالأمر deploy-iis.ps1 -SiteName Bayan -PhysicalPath <مجلد الموقع>؛ فالسكربت يرفض إنشاء موقع ثانٍ، لأنه سيشغّل كل تصدير مجدول مرتين.

Changing and rebuilding offline

A run-only release cannot be changed. To edit and rebuild on a machine that never touches the internet, carry the toolchains and the package caches the build restores from. prepare-offline-bundle.ps1 does all of it; the pieces are:

Build the bundle with the SDK it ships

The SDK version at the top of the script decides the .NET runtime inside the API, which is what the server runs until the next bundle. An isolated server gets security fixes only this way: at each .NET or Node.js security release, raise the versions at the top of the script and build the bundle again. A bundle made before Arabic support or before the SQL editor lacks packages added since; build it again.

Prove it before you disconnect: switch the network off on the preparing machine and run the rebuild loop below. If it works, the server has everything it needs.

ابنِ الحزمة بإصدار SDK الذي تحمله

إصدار SDK في أعلى السكربت يحدد بيئة .NET داخل الـAPI، وهي ما يعمل به الخادم حتى الحزمة التالية. والخادم المعزول لا يحصل على إصلاحات الأمان إلا بهذه الطريقة: مع كل إصدار أمني لـ.NET أو Node.js، ارفع الإصدارات في أعلى السكربت وابنِ الحزمة من جديد. والحزمة المبنية قبل دعم العربية أو قبل محرر SQL تنقصها حزم أُضيفت بعدها؛ فابنِها من جديد.

تأكد قبل الانفصال: افصل الشبكة على جهاز التحضير، وشغّل حلقة إعادة البناء أدناه. فإن نجحت، فلدى الخادم كل ما يحتاجه.

The AI bundle (optional)

The AI assistant runs on a model on the server itself. It comes in its own bundle, apart from offline-bundle/: the models are many gigabytes and rarely change, so they are not carried again with every update. Without it, Jadwal works as before and shows no AI buttons.

حزمة الذكاء الاصطناعي (اختيارية)

يعمل المساعد الذكي بنموذج على الخادم نفسه، ويأتي في حزمة مستقلة عن offline-bundle/: فالنماذج بحجم غيغابايتات كثيرة ونادرًا ما تتغير، فلا تُنقل مع كل تحديث. وبدونها يعمل «جدول» كما كان ولا يعرض أي زر للذكاء الاصطناعي.

1 · Build it (connected machine)

١ · بناؤها (جهاز متصل)

powershell -ExecutionPolicy Bypass -File scripts\prepare-ai-bundle.ps1 -OutDir 'E:\Jadwal-AI-Bundle'
  • Downloads a pinned Ollama release and pulls Gemma 4 12B and Qwen3.5 9B, about 18 GB. Point -OutDir at a drive with about 20 GB free; the script checks first.
  • The models are pulled through a private copy of Ollama on its own port, so an Ollama already on that machine is left alone.
  • Options:
    • -Models 'gemma4:12b' for one model, or -Models 'qwen3:4b' for a small model (about 2.5 GB) for a CPU-only server or as a stopgap;
    • -ReuseModelsFrom "$env:USERPROFILE\.ollama\models" takes models already pulled on this machine instead of downloading them again (each file is checked against its checksum, and linked rather than copied on the same drive);
    • -AllowUntrustedDownload for a machine that does not trust the certificate of GitHub's download host: the Ollama zip is then accepted only if it matches the SHA-256 that GitHub's API publishes for it;
    • -IncludeRocm for AMD GPUs, -OllamaVersion for another release.
  • Every Ollama download is checked against the SHA-256 that GitHub publishes for it.
  • It writes ollama/, models/, install-ai-service.ps1, MANIFEST.txt and SHA256SUMS.txt. Copy the whole folder to the server.
  • ينزّل إصدارًا محددًا من Ollama ويسحب Gemma 4 12B وQwen3.5 9B، نحو 18 غيغابايت. وجّه -OutDir إلى قرص فيه نحو 20 غيغابايت فارغة؛ والسكربت يتحقق أولًا.
  • تُسحب النماذج عبر نسخة خاصة من Ollama على منفذ مستقل، فلا يُمس أي Ollama موجود على ذلك الجهاز.
  • الخيارات:
    • -Models 'gemma4:12b' لنموذج واحد، أو -Models 'qwen3:4b' لنموذج صغير (نحو 2.5 غيغابايت) لخادم بلا بطاقة رسومات أو حلًا مؤقتًا؛
    • -ReuseModelsFrom "$env:USERPROFILE\.ollama\models" يأخذ النماذج المسحوبة على هذا الجهاز بدل تنزيلها من جديد (يُفحص كل ملف ببصمته، ويُربط بدل نسخه إن كان على القرص نفسه)؛
    • -AllowUntrustedDownload لجهاز لا يثق بشهادة خادم التنزيل في GitHub: فلا يُقبل ملف Ollama إلا إذا طابق بصمة SHA-256 التي تنشرها واجهة GitHub البرمجية؛
    • -IncludeRocm لبطاقات AMD، و-OllamaVersion لإصدار آخر.
  • كل ملف Ollama يُنزَّل يُفحص مقابل بصمة SHA-256 التي ينشرها GitHub.
  • يكتب ollama/ وmodels/ وinstall-ai-service.ps1 وMANIFEST.txt وSHA256SUMS.txt. انسخ المجلد كاملًا إلى الخادم.

2 · Install it (on the server, as administrator)

٢ · تثبيتها (على الخادم، بصلاحيات المسؤول)

powershell -ExecutionPolicy Bypass -File .\install-ai-service.ps1
  1. Checks every file against SHA256SUMS.txt and stops on a damaged copy.
  2. Installs Ollama to C:\Ollama and the models to C:\OllamaModels (-InstallDir, -ModelsDir; a local disk, not a share).
  3. Writes start-ollama.cmd: it listens on 127.0.0.1 only, since Ollama has no login of its own; keeps the model loaded; answers one request at a time.
  4. Registers the task "Jadwal AI (Ollama)", started at boot as SYSTEM and restarted if it stops, then checks the models answer.
  5. Reads the GPU and prints the Ai section to paste: gemma4:12b with 12 GB or more, else qwen3.5:9b; with neither in the bundle, the model it carries.

Run it again to upgrade: it replaces the runtime and keeps the models already there. Then follow Switching it on.

  1. يتحقق من كل ملف مقابل SHA256SUMS.txt ويتوقف عند أي نسخة تالفة.
  2. يثبّت Ollama في C:\Ollama والنماذج في C:\OllamaModels (-InstallDir و-ModelsDir؛ على قرص محلي لا مجلد مشترك).
