About the system

Jadwal brings running database queries into one place. A query is defined and saved once, and tied to an approved database connection whose credentials are managed centrally, instead of queries living in tools and files on people's own computers.

Automation is built on that. Any query can be scheduled to run on its own, daily, weekly or monthly, and write its output to an approved folder in the format needed. Regular extracts are ready on time without anyone having to be there. Every run is recorded with who ran it, when, and how it ended, which gives a trail to come back to at a review or an audit.

Once a query is defined centrally, it can be offered to the people allowed to use it: they reach a simple screen, fill in what is needed (a date, a branch, a status), see the result, and export it to Excel, PDF or Word, with no request to IT each time. Several queries can be combined into one report with an official template, and the key figures shown on dashboards that refresh by themselves, under the same permissions.

نبذة عن النظام

يجمع النظام تشغيل الاستعلامات على قواعد البيانات في مكان واحد: يُعرَّف الاستعلام ويُحفظ مرة واحدة، ويُربط باتصال قاعدة بيانات معتمد تُدار بياناته مركزيًا، بدل أن تبقى الاستعلامات موزّعة في أدوات وملفات على أجهزة الأفراد.

وعلى هذا الأساس تقوم الأتمتة: يمكن جدولة أي استعلام ليعمل من تلقاء نفسه، يوميًا أو أسبوعيًا أو شهريًا، وتُحفظ مخرجاته في مجلد معتمد وبالصيغة المطلوبة، فتكون عمليات الاستخراج الدورية جاهزة في موعدها دون تدخّل أحد. ويُسجَّل كل تشغيل باسم صاحبه ووقته ونتيجته، فيبقى سجل موثّق يُرجع إليه عند المراجعة أو التدقيق.

ومتى صار الاستعلام معرَّفًا مركزيًا، أمكن إتاحته للمستخدمين المخوَّلين: يصل الموظف إلى شاشة بسيطة يملأ فيها ما يلزم (تاريخ، أو فرع، أو حالة معاملة)، فتظهر النتيجة أمامه ويصدّرها إلى Excel أو PDF أو Word، دون الرجوع في كل مرة إلى قسم تقنية المعلومات. ويمكن جمع عدة استعلامات في تقرير واحد بقالب رسمي، وعرض المؤشرات الرئيسية في لوحات معلومات تحدّث نفسها تلقائيًا، بالصلاحيات نفسها.

How it is built

Clean Architecture with CQRS. Each layer depends only on the ones below it; the domain depends on nothing. One API process serves the screens, runs the background work, and talks to the databases, the directory and, optionally, the local AI model.

كيف بُني

بنية نظيفة (Clean Architecture) مع فصل الأوامر عن الاستعلامات (CQRS). كل طبقة تعتمد على ما تحتها فقط، وطبقة النطاق لا تعتمد على شيء. عملية API واحدة تخدم الشاشات، وتشغّل الأعمال في الخلفية، وتتصل بقواعد البيانات والدليل، وبنموذج الذكاء الاصطناعي المحلي إن وُجد.
