Overview

Features

Everything Jadwal does, and the reasoning behind the parts that behave in ways you might not expect. Screen-by-screen steps are in the Word user manuals.

نظرة عامة

الخصائص

كل ما يقدّمه «جدول»، مع سبب كل سلوك قد لا تتوقعه. أما الشرح شاشةً شاشة، فهو في دليلي المستخدم بصيغة Word.

Saved queries

An administrator writes the SQL once, gives it input fields, and grants it to roles, user groups or named people. Everyone it is granted to finds it under My Queries, fills in the form, and runs it.

The administrator

  • Writes parameterised SQL in a colour-coded editor, and tests it (at most 100 rows) before saving.
  • Defines input fields: text, number, date, yes/no, and drop-downs filled from a fixed list or from another query.
  • Lets a text field take several values, used as IN (@p).
  • Puts queries in query groups (folders), switches them on and off, sets a timeout.
  • Picks the database connection and the formats a result may be exported as.

The user

  • Sees only the queries granted to them.
  • Fills in a form built from the fields, and runs it.
  • Searches, sorts and filters the result, page by page.
  • Exports it as Excel, CSV, JSON, PDF or Word, where allowed.
  • Sees their own run history.

No value is ever pasted into SQL

Queries are written with @name placeholders and [bracket] names, and adapted to each database when they run. Every value is bound through the driver.

الاستعلامات المحفوظة

يكتب المسؤول نص SQL مرة واحدة، ويضع له حقول إدخال، ويمنحه لأدوار أو مجموعات مستخدمين أو أشخاص بأسمائهم. فيجده كل من مُنح له في صفحة الاستعلامات، فيملأ النموذج ويشغّله.

المسؤول

  • يكتب SQL بمعايير بحث في محرر ملوَّن، ويختبره (100 صف على الأكثر) قبل الحفظ.
  • يحدد حقول الإدخال: نص، ورقم، وتاريخ، ونعم/لا، وقوائم منسدلة من قائمة ثابتة أو من استعلام آخر.
  • يسمح لحقل نصي بأخذ عدة قيم، تُستخدم بالشكل IN (@p).
  • يضع الاستعلامات في مجموعات (مجلدات)، ويفعّلها أو يوقفها، ويحدد مهلة التنفيذ.
  • يختار اتصال قاعدة البيانات، والصيغ التي يجوز تصدير النتيجة بها.

المستخدم

  • لا يرى إلا الاستعلامات الممنوحة له.
  • يملأ نموذجًا مبنيًا من الحقول، ثم يشغّله.
  • يبحث في النتيجة ويرتّبها ويصفّيها، صفحةً صفحة.
  • يصدّرها إلى Excel أو CSV أو JSON أو PDF أو Word، حيث يُسمح بذلك.
  • يرى سجل تشغيله الخاص.

لا تُلصق أي قيمة داخل نص SQL

تُكتب الاستعلامات بعلامات @name وأسماء بين أقواس [bracket]، وتُكيَّف لكل نوع قاعدة بيانات عند التشغيل. وكل قيمة تُمرَّر عبر برنامج التشغيل (driver) لا عبر النص.

Databaseقاعدة البياناتNames written asتُكتب الأسماءValues bound asتُمرَّر القيم
SQL Server[bracket]@param
Oracle"double-quote":param
PostgreSQL"double-quote"@param
MySQL`backtick`@param

A multi-value field expands IN (@names) to IN (@names_0, @names_1, …), each bound on its own; an empty list becomes IN (NULL) and matches nothing. An empty optional field arrives as NULL, so an optional filter is written (@p IS NULL OR col = @p).

الحقل متعدد القيم يحوّل IN (@names) إلى IN (@names_0, @names_1, …)، وتُمرَّر كل قيمة وحدها؛ والقائمة الفارغة تصبح IN (NULL) فلا تطابق شيئًا. والحقل الاختياري الفارغ يصل بقيمة NULL، لذا يُكتب الشرط الاختياري هكذا: (@p IS NULL OR col = @p).

Results: run once, page and export from memory

A read query runs once. The whole result, with no row limit, is kept on the server, and the browser gets only the page it is showing. Sorting, filtering and moving between pages read that kept copy; exporting builds the file from it too. Looking at a slow query and then exporting it costs one run, not two.

النتائج: تشغيل واحد، ثم التصفح والتصدير من الذاكرة

يعمل استعلام القراءة مرة واحدة. تُحفظ النتيجة كاملة على الخادم دون حد للصفوف، ولا يصل إلى المتصفح إلا الصفحة المعروضة. فالترتيب والتصفية والتنقل بين الصفحات تقرأ من النسخة المحفوظة، والتصدير يبني الملف منها كذلك. فعرض استعلام بطيء ثم تصديره يكلّف تشغيلًا واحدًا لا اثنين.

How long it is kept. Until the user leaves the results page, which releases it at once. As a fallback (a closed tab, a crash) each result is kept for a sliding window that restarts on every page or export, one day by default (ResultCache:RetentionMinutes).

query.maxRows (default 10,000) is not a display limit: it caps only the internal reads that must hold a whole result at once, such as write previews and drop-down lists.

مدة الحفظ. حتى يغادر المستخدم صفحة النتائج، فتُحرَّر فورًا. واحتياطًا (تبويب أُغلق أو تعطّل مفاجئ) تُحفظ كل نتيجة مدةً تتجدد مع كل صفحة أو تصدير، يومًا واحدًا افتراضيًا (ResultCache:RetentionMinutes).

الإعداد query.maxRows (افتراضيًا 10,000) ليس حدًا للعرض: إنما يحدّ القراءات الداخلية التي تحتاج النتيجة كاملة دفعة واحدة، مثل معاينة التعديل والقوائم المنسدلة.

Export: two gates that must agree

Downloading a result needs both of these:

  1. The query lists the formats it may be exported as at all (Excel, CSV, PDF, Word, JSON), under Result export on its form. Tick none and nobody can download it.
  2. The role holds the formats this person may use: queries.exportExcel, …Csv, …Json, …Pdf, …Word.

The export menu shows only the formats both allow, and the download endpoint checks both again, since hiding a menu item is not a control. Reports work the same way with their own list and reports.export* permissions.

An upgrade closes export everywhere

The migration that added this gave every existing query an empty format list and no role any export permission. Downloads stop until an administrator opens them. That is on purpose: the alternative would quietly keep exporting data you may have wanted to restrict.

Scheduled tasks are not gated this way. They write files on the server from a task that already needs scheduledTasks.manage. So anyone who can create a scheduled task can still produce a file from a query whose export is off. Grant that permission accordingly.

PDF from a Word template is rendered to .docx first, then converted by LibreOffice (preferred) or Microsoft Word if installed. With neither, a built-in PDF layout is used, without the template's styling. Choose with Export:PdfEngine (auto | libreoffice | word | builtin).

التصدير: بوّابتان يجب أن تتفقا

تنزيل النتيجة يحتاج الأمرين معًا:

  1. الاستعلام يحدد الصيغ التي يجوز تصديره بها أصلًا (Excel وCSV وPDF وWord وJSON)، في قسم تصدير النتائج من نموذجه. وإن لم تُختر أي صيغة فلن يستطيع أحد تنزيله.
  2. الدور يحمل الصيغ التي يجوز لهذا الشخص استخدامها: queries.exportExcel و…Csv و…Json و…Pdf و…Word.

قائمة التصدير لا تعرض إلا ما يسمح به الطرفان، ونقطة التنزيل تتحقق من الاثنين مرة أخرى، لأن إخفاء خيار من القائمة ليس حماية. والتقارير تعمل بالطريقة نفسها، بقائمتها الخاصة وصلاحيات reports.export*.

الترقية تغلق التصدير في كل مكان

الترحيل الذي أضاف هذه الميزة أعطى كل استعلام موجود قائمة صيغ فارغة، ولم يمنح أي دور صلاحية تصدير. فيتوقف التنزيل حتى يفتحه المسؤول. وهذا مقصود: البديل أن يستمر تصدير بيانات ربما أردت تقييدها دون أن تنتبه.

المهام المجدولة لا تخضع لهاتين البوابتين. فهي تكتب الملفات على الخادم من مهمة تحتاج أصلًا صلاحية scheduledTasks.manage. أي أن من يستطيع إنشاء مهمة مجدولة يستطيع إخراج ملف من استعلام تصديره مغلق، فامنح هذه الصلاحية بحذر.

ملف PDF من قالب Word يُبنى أولًا ملف .docx، ثم يحوّله LibreOffice (المفضّل) أو Microsoft Word إن كان مثبتًا. وإن لم يوجد أي منهما، يُستخدم تصميم PDF مدمج دون تنسيق القالب. ويُختار ذلك من Export:PdfEngine (auto | libreoffice | word | builtin).

Queries that change data

A saved query can be an INSERT, UPDATE or DELETE. These run in two steps, so the user sees what will change before it does.

الاستعلامات التي تعدّل البيانات

يمكن أن يكون الاستعلام المحفوظ INSERT أو UPDATE أو DELETE. وهذه تعمل على خطوتين، ليرى المستخدم ما سيتغيّر قبل أن يتغيّر.

  • The kind is decided when the query is saved. The server reads the main statement, skipping string literals, comments and any WITH list, and stores Select/Insert/Update/Delete/Other. It is never taken from the browser. WITH … DELETE is a delete, and goes through preview and confirm.
  • Run directly without preview. Offered only when the query's Allow running without confirmation is on (the default). It saves two round trips on big tables. It is a convenience in the screens, not a server-side control.
  • Before-change values. For UPDATE and DELETE the matching rows are read and stored in the execution log before the change. Turn Save before-change values off for statements that touch very many rows.
  • Scheduled tasks always run writes confirmed: there is nobody to confirm.
  • Other (MERGE, DDL, a PL/SQL block) is not treated as a write.
  • نوع الاستعلام يُحدَّد عند حفظه. يقرأ الخادم الجملة الرئيسية، متجاوزًا النصوص بين علامات التنصيص والتعليقات وقائمة WITH، ويحفظ النوع Select/Insert/Update/Delete/Other. ولا يُؤخذ من المتصفح أبدًا. والجملة WITH … DELETE تُعدّ حذفًا، فتمرّ بالمعاينة والتأكيد.
  • التشغيل المباشر دون معاينة. لا يظهر إلا إذا كان خيار السماح بالتشغيل دون تأكيد مفعّلًا في الاستعلام (وهو الافتراضي). يوفّر خطوتين على الجداول الكبيرة. وهو تسهيل في الشاشات، لا حماية على الخادم.
  • القيم قبل التغيير. في UPDATE وDELETE تُقرأ الصفوف المطابقة وتُحفظ في سجل التنفيذ قبل التغيير. أوقف خيار حفظ القيم قبل التغيير في الجمل التي تمسّ عددًا كبيرًا جدًا من الصفوف.
  • المهام المجدولة تشغّل التعديل مؤكَّدًا دائمًا، إذ لا يوجد من يؤكّد.
  • النوع Other (مثل MERGE أو تعريف الجداول أو كتلة PL/SQL) لا يُعامل معاملة التعديل.

Long-running queries

A request that waits for a slow query is cut off by whatever sits in front of the app (IIS and nginx at about 2 minutes, some proxies sooner), whatever the query's own timeout says. A query flagged long-running avoids that: the browser submits it, gets a job number at once, and asks every 2 seconds until it finishes. Every request stays short.

  • Up to 4 jobs run at the same time in the background, through exactly the same checks and logging as a normal run.
  • The user sees a live timer and a Cancel button. Cancelling really stops the database command and frees the connection.
  • Only the job's owner, or an Admin, can see or cancel it.
  • Jobs live in the API's memory. A restart loses them (the user is told to run again), which is why IIS must not recycle on its own (IIS hosting), and why only one copy of the API may run.

الاستعلامات طويلة التشغيل

الطلب الذي ينتظر استعلامًا بطيئًا يقطعه ما يقف أمام التطبيق (IIS وnginx بعد نحو دقيقتين، وبعض الوسطاء أسرع)، مهما كانت مهلة الاستعلام نفسه. والاستعلام المعلَّم بأنه طويل التشغيل يتجنب ذلك: يرسله المتصفح، فيأخذ رقم مهمة فورًا، ثم يسأل عنه كل ثانيتين حتى ينتهي. فتبقى كل الطلبات قصيرة.

  • تعمل حتى 4 مهام في الخلفية في الوقت نفسه، بالتحقق والتسجيل نفسيهما في التشغيل العادي.
  • يرى المستخدم عدّادًا حيًا وزر إلغاء. والإلغاء يوقف الأمر في قاعدة البيانات فعلًا ويحرّر الاتصال.
  • لا يرى المهمة أو يلغيها إلا صاحبها أو مسؤول (Admin).
  • المهام في ذاكرة الـAPI، فإعادة التشغيل تفقدها (ويُطلب من المستخدم التشغيل مجددًا). لهذا يجب ألا يعيد IIS تدوير التطبيق من تلقاء نفسه (الاستضافة على IIS)، ولهذا لا تعمل إلا نسخة واحدة من الـAPI.

Scheduled tasks

A scheduled task runs one or more queries or reports on a timetable and writes the files to a folder, with nobody at the screen.

When

  • Every N minutes, daily, weekly or monthly, with several triggers per task.
  • On demand, with Run now; a running task can be cancelled.

What it writes

  • Excel, CSV or JSON (and a report's own formats), one file per item or all in one.
  • An output folder and an optional archive copy; a timestamp in the name, in a format you choose.
  • CSV with any separator, with or without headers, appended to one growing file if wanted.

Incremental items. Give an item a key column and it exports only rows added since the last run: the last key is remembered and bound into the next run. A failed run does not move the checkpoint, so nothing is skipped.

Who sees it. Managers (scheduledTasks.manage) see everything. Other people see a task when it is shared with their role, user group or name, and can download its files only with scheduledTasks.download and the task's own "can download" setting.

The scheduler runs inside the API. If the API is stopped, or IIS lets it idle, tasks do not run and nothing tells you. The account the API runs as needs write access to every output and archive folder.

المهام المجدولة

المهمة المجدولة تشغّل استعلامًا أو تقريرًا أو أكثر في مواعيد محددة، وتكتب الملفات في مجلد، دون أن يجلس أحد أمام الشاشة.

متى

  • كل عدد من الدقائق، أو يوميًا أو أسبوعيًا أو شهريًا، ولكل مهمة عدة مواعيد.
  • عند الطلب بزر تشغيل الآن، ويمكن إلغاء مهمة قيد التشغيل.

ماذا تكتب

  • Excel أو CSV أو JSON (وصيغ التقرير الخاصة)، ملفًا لكل عنصر أو الكل في ملف واحد.
  • مجلد إخراج ونسخة أرشيف اختيارية، مع ختم وقت في الاسم بالتنسيق الذي تختاره.
  • CSV بأي فاصل، مع العناوين أو بدونها، وإضافة إلى ملف واحد ينمو إن أردت.

العناصر التزايدية. حدّد لعنصر عمود مفتاح، فلا يصدّر إلا الصفوف التي أُضيفت منذ آخر تشغيل: تُحفظ آخر قيمة للمفتاح وتُمرَّر في التشغيل التالي. والتشغيل الفاشل لا يحرّك نقطة التوقف، فلا يضيع شيء.

من يراها. من يملك صلاحية scheduledTasks.manage يرى كل شيء. وغيرهم يرى المهمة إذا شوركت مع دوره أو مجموعته أو اسمه، ولا ينزّل ملفاتها إلا بصلاحية scheduledTasks.download مع خيار «يمكنه التنزيل» في المهمة نفسها.

المجدول يعمل داخل الـAPI. فإذا توقف الـAPI، أو تركه IIS خاملًا، لا تعمل المهام ولا يُخبرك شيء بذلك. والحساب الذي يعمل به الـAPI يحتاج صلاحية الكتابة في كل مجلد إخراج وأرشيف.

Reports

A report puts several saved queries into one document. Each section reads a query, joins two of them, or shows detail rows under a master row. Report parameters are filled once and passed to each query. Charts (column, bar, line, pie, area, stacked, doughnut, combo) are drawn from a section's rows.

A Word template gives the report the organisation's look: place {{RESULTS:key}} and {{CHART:key}} markers where each section goes. Without a template, a clean built-in layout is used. The exported document can carry who produced it and when.

A report never widens access

Running a report needs the report grant and the right to run every query inside it. A section the person could not run on their own is refused and shown as a warning; the rest of the report still runs.

التقارير

يجمع التقرير عدة استعلامات محفوظة في مستند واحد. كل قسم يقرأ استعلامًا، أو يربط استعلامين، أو يعرض صفوفًا تفصيلية تحت صف رئيسي. وتُملأ معايير بحث التقرير مرة واحدة وتُمرَّر لكل استعلام. وتُرسم المخططات (أعمدة، أشرطة، خطوط، دائرية، مساحية، مكدّسة، حلقية، مركّبة) من صفوف القسم.

قالب Word يعطي التقرير شكل الجهة: ضع العلامتين {{RESULTS:key}} و{{CHART:key}} حيث يأتي كل قسم. وبدون قالب يُستخدم تصميم مدمج مرتب. ويمكن أن يحمل المستند المصدَّر اسم من أصدره ووقت إصداره.

التقرير لا يوسّع الصلاحيات أبدًا

تشغيل التقرير يحتاج منح التقرير وحق تشغيل كل استعلام فيه. والقسم الذي لا يستطيع الشخص تشغيله وحده يُرفض ويظهر تنبيهًا، ويعمل باقي التقرير.

Dashboards

A dashboard is a page of tiles, each fed by a saved query and refreshed on its own interval (30 seconds to an hour). Tiles come in 14 kinds: KPI, column, bar, line, area, pie, doughnut, stacked column, stacked bar, combo, gauge, funnel, heatmap and table. Dashboard filters feed the tiles' query parameters, and clicking a chart can filter the dashboard, open a report, or show the rows behind it.

  • Shared results. A tile's result is kept for its interval for each set of filter values, so ten people watching the same dashboard cost one query per tile per interval, not ten.
  • Checked before the shared copy is read. Each tile checks the dashboard grant, the tile query's grant and its connection, so a warm copy is never handed to someone who could not have produced it. A tile the viewer cannot run stays empty with a message.
  • Read only. A dashboard refuses a query that changes data.

لوحات المعلومات

لوحة المعلومات صفحة من البطاقات، كل بطاقة يغذّيها استعلام محفوظ وتتحدث في موعدها الخاص (من 30 ثانية إلى ساعة). وللبطاقات 14 نوعًا: مؤشر رئيسي، وأعمدة، وأشرطة، وخطوط، ومساحي، ودائري، وحلقي، وأعمدة مكدّسة، وأشرطة مكدّسة، ومركّب، وعدّاد، وقمعي، وخريطة حرارية، وجدول. ومرشّحات اللوحة تغذّي معايير بحث استعلامات البطاقات، والنقر على مخطط يمكن أن يصفّي اللوحة أو يفتح تقريرًا أو يعرض الصفوف التي خلفه.

  • نتائج مشتركة. تُحفظ نتيجة البطاقة طوال مدة تحديثها لكل مجموعة قيم مرشحات، فعشرة أشخاص يشاهدون اللوحة نفسها يكلّفون استعلامًا واحدًا لكل بطاقة في كل مدة، لا عشرة.
  • التحقق قبل قراءة النسخة المشتركة. كل بطاقة تتحقق من منح اللوحة، ومنح استعلام البطاقة واتصاله، فلا تُعطى النسخة المحفوظة لمن لم يكن يستطيع إنتاجها. والبطاقة التي لا يستطيع المشاهد تشغيلها تبقى فارغة مع رسالة.
  • للقراءة فقط. ترفض اللوحة أي استعلام يعدّل البيانات.

User groups and query groups

Access is granted to roles, to user groups, or to named users. User groups are kept inside Jadwal (Users and permissions → User groups), and are not a copy of Active Directory. One group can hold directory accounts and local accounts side by side.

  • Membership is checked on every request: removing someone takes effect on their next click.
  • Nobody can add themselves to a group. An account an administrator already placed there stays, and may leave.
  • Deleting a group removes its grants; the accounts are untouched.
  • Query groups are folders of queries. Granting a query group grants everything in it.

The directory's department is still stored on imported accounts and drives the Active Directory users page, where you browse and import people. It no longer decides what anyone can reach.

مجموعات المستخدمين ومجموعات الاستعلامات

يُمنح الوصول إلى أدوار، أو مجموعات مستخدمين، أو مستخدمين بأسمائهم. ومجموعات المستخدمين تُدار داخل «جدول» (المستخدمون والصلاحيات ← مجموعات المستخدمين)، وليست نسخة من Active Directory. والمجموعة الواحدة تضم حسابات الدليل والحسابات المحلية معًا.

  • تُفحص العضوية مع كل طلب: إزالة شخص تسري من نقرته التالية.
  • لا يستطيع أحد إضافة نفسه إلى مجموعة. والحساب الذي وضعه المسؤول فيها يبقى، ويمكنه الخروج.
  • حذف المجموعة يزيل ما مُنح لها، ولا يمسّ الحسابات.
  • مجموعات الاستعلامات مجلدات للاستعلامات. ومنح مجموعة استعلامات يمنح كل ما فيها.

ما زال القسم في الدليل يُحفظ مع الحسابات المستوردة، ويُستخدم في صفحة مستخدمو Active Directory لتصفح الأشخاص واستيرادهم. لكنه لم يعد يحدد ما يصل إليه أحد.

Backup and moving between systems

Queries, reports and dashboards can be exported to a file and imported on the same or another system.

  • Everything travels by name, not by id. Query groups are created if missing; connections, roles, users and user groups are matched by name, and anything unmatched is reported. A drop-down that reads another query is linked in a second pass, after everything in the file exists.
  • Passwords never travel. Only the connection's name is written. Set up the connection on the new system and the name links it back.
  • Import never overwrites. A name already taken is imported as Name (imported). A mistaken import is undone by deleting what it added.
  • The statement kind is worked out again from the SQL, not trusted from the file. Word templates travel inside it.

النسخ الاحتياطي والنقل بين الأنظمة

يمكن تصدير الاستعلامات والتقارير ولوحات المعلومات إلى ملف، واستيرادها في النظام نفسه أو في نظام آخر.

  • كل شيء ينتقل بالاسم لا بالمعرّف. تُنشأ مجموعات الاستعلامات إن لم توجد، ويُطابَق كل من الاتصالات والأدوار والمستخدمين ومجموعات المستخدمين بالاسم، وما لم يُطابَق يُذكر في النتيجة. والقائمة المنسدلة التي تقرأ استعلامًا آخر تُربط في جولة ثانية، بعد أن يوجد كل ما في الملف.
  • كلمات المرور لا تنتقل أبدًا. لا يُكتب إلا اسم الاتصال. أنشئ الاتصال في النظام الجديد فيرتبط بالاسم.
  • الاستيراد لا يكتب فوق شيء. الاسم المستخدم من قبل يُستورد باسم Name (imported). والاستيراد الخاطئ يُلغى بحذف ما أضافه.
  • نوع الجملة يُستخرج من SQL من جديد، ولا يُؤخذ من الملف. وقوالب Word تنتقل داخله.

Logo, site name and tab icon

From the account menu, Website branding sets the banner logo, a site name for each language, and the browser tab icon (branding.manage).

  • The banner shows the logo, else the site name in the current language, else the app's name, so it is never blank.
  • Logo: PNG, JPG or WebP up to 1 MB, shown 40 px tall (upload 80 px for sharp screens). Tab icon: PNG, ICO or WebP up to 256 KB, uploaded separately because a wide logo shrunk to 16 px is a smudge.
  • SVG is refused: it can carry script, and these images are served without sign-in. Files are checked by their content, not only their extension.
  • The logo and tab icon are served without sign-in because the browser fetches them for the sign-in page itself.

الشعار واسم الموقع وأيقونة التبويب

من قائمة الحساب، تضبط هوية الموقع شعار الشريط العلوي، واسم الموقع لكل لغة، وأيقونة تبويب المتصفح (صلاحية branding.manage).

  • يعرض الشريط الشعار، وإلا فاسم الموقع باللغة الحالية، وإلا فاسم التطبيق، فلا يكون فارغًا أبدًا.
  • الشعار: PNG أو JPG أو WebP حتى 1 ميغابايت، ويُعرض بارتفاع 40 بكسل (ارفعه بارتفاع 80 ليكون واضحًا على الشاشات الدقيقة). أيقونة التبويب: PNG أو ICO أو WebP حتى 256 كيلوبايت، تُرفع وحدها لأن الشعار العريض إذا صُغّر إلى 16 بكسل صار بقعة.
  • صيغة SVG مرفوضة: قد تحمل شيفرة برمجية، وهذه الصور تُقدَّم دون تسجيل دخول. وتُفحص الملفات بمحتواها لا بامتدادها فقط.
  • الشعار والأيقونة يُقدَّمان دون تسجيل دخول لأن المتصفح يطلبهما لصفحة تسجيل الدخول نفسها.

English and Arabic

The whole interface is in English and Arabic, switched from the top bar (and on the sign-in page). One build serves both. Arabic lays the screens out right to left.

PartHow
Screen textTransloco, client/src/assets/i18n/en.json and ar.json
Directionlanguage.service.ts sets lang and dir on the page; Angular Material mirrors itself
Server messagesMessages.resx / Messages.ar.resx, chosen by Accept-Language
Arabic fontCairo, shipped inside the app (no web fonts)

Rules for anyone adding text: put each key in both files; never join a translated piece to a value (use placeholders, since word order differs); wrap user names and paths in Arabic text in direction isolates; give content people typed (query names, result cells) dir="auto", and SQL .force-ltr; use logical CSS (margin-inline-start, never margin-left).

Not covered: Arabic-Indic digits, Hijri dates, and right-to-left layout inside exported PDF, Word and Excel files.
