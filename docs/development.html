Running it locally

You need the .NET 10 SDK, Node.js 24 with npm 10, a database you can reach (Oracle, SQL Server, MySQL or PostgreSQL), and an LDAP or Active Directory server for directory sign-in (local accounts work without one).

التشغيل محليًا

تحتاج .NET 10 SDK، وNode.js 24 مع npm 10، وقاعدة بيانات تصل إليها (Oracle أو SQL Server أو MySQL أو PostgreSQL)، وخادم LDAP أو Active Directory لدخول حسابات الدليل (والحسابات المحلية تعمل بدونه).

# API: http://localhost:5000, API docs at /swagger
dotnet restore Jadwal.sln
dotnet run --project src/Jadwal.API

# Client: http://localhost:4200, passes /api to the API
cd client
npm install
npm start

On first start the API creates the schema, seeds the four roles and the development accounts (see Security), and applies any pending migrations. Windows sign-in cannot be tested under ng serve; it only works when IIS hosts both halves.

عند أول تشغيل ينشئ الـAPI المخطط، ويضيف الأدوار الأربعة وحسابات التطوير (انظر الأمان)، ويطبّق أي ترحيلات معلّقة. ولا يمكن اختبار الدخول بحساب Windows مع ng serve؛ فهو لا يعمل إلا حين يستضيف IIS الجزأين معًا.

Conventions worth knowing

  • Every command is audited automatically. Give a new command a readable label in AuditActions.Map and a translation under admin.audit.actions in both catalogs; without one it is still recorded, under other.
  • Endpoints name permissions. Use [RequirePermission(...)]; several in one attribute mean any of them, several attributes mean all of them. A new permission starts closed for every role but Admin.
  • Server messages go through IAppLocalizer and both .resx files; screen text through both i18n catalogs.
  • The client runs without zone.js change detection. After work outside Angular's own events, mark the view for checking.
  • Messages and confirmations use the shared toast and confirm services, which take translation keys directly.
  • Oracle: follow the migration rules.

أعراف يجدر معرفتها

  • كل أمر يُسجَّل تلقائيًا. أعطِ الأمر الجديد اسمًا مقروءًا في AuditActions.Map وترجمة تحت admin.audit.actions في الملفين؛ وبدونهما يُسجَّل أيضًا تحت other.
  • نقاط الوصول تطلب صلاحيات. استخدم [RequirePermission(...)]؛ عدة صلاحيات في سمة واحدة تعني إحداها، وعدة سمات تعني كلها. والصلاحية الجديدة تبدأ مغلقة لكل الأدوار ما عدا Admin.
  • رسائل الخادم تمر عبر IAppLocalizer وملفي .resx، ونصوص الشاشات عبر ملفي الترجمة.
  • الواجهة تعمل دون كشف التغييرات التلقائي من zone.js. بعد أي عمل خارج أحداث Angular نفسها، علّم العرض للتحديث.
  • الرسائل والتأكيدات تستخدم خدمتي الإشعار والتأكيد المشتركتين، اللتين تأخذان مفاتيح الترجمة مباشرة.
  • Oracle: اتبع قواعد الترحيل.

The QueryRunner tool

A small console program in tools/Jadwal.QueryRunner that runs one or more SELECT queries from a JSON file and writes the results as Excel, CSV or JSON, made for Windows Task Scheduler. It is fully independent: no API, no Jadwal database, no sign-in, and no reference to the other projects. Its files use the same layout as the web app's exports.

أداة QueryRunner

برنامج صغير لسطر الأوامر في tools/Jadwal.QueryRunner يشغّل استعلام SELECT أو أكثر من ملف JSON ويكتب النتائج بصيغة Excel أو CSV أو JSON، مصمَّم لـTask Scheduler في Windows. وهو مستقل تمامًا: لا API، ولا قاعدة بيانات «جدول»، ولا تسجيل دخول، ولا ارتباط بالمشاريع الأخرى. وملفاته بالتصميم نفسه لتصدير التطبيق.

dotnet publish tools\Jadwal.QueryRunner -c Release -o C:\Tools\QueryRunner

Jadwal.QueryRunner.exe                       # reads appsettings.json next to the exe
Jadwal.QueryRunner.exe C:\Jobs\sales.json    # or any config: one file per scheduled job

Only new rows each time

Give a query a KeyColumn: the last key exported is saved and bound into the next run, so only newer rows come out. Always ORDER BY the key ascending and select it. A failed run does not move the checkpoint, so nothing is skipped; delete the state file to start over.

الصفوف الجديدة فقط في كل مرة

حدّد للاستعلام KeyColumn: تُحفظ آخر قيمة مفتاح صُدّرت وتُمرَّر في التشغيل التالي، فلا يخرج إلا الأحدث. رتّب دائمًا بالمفتاح تصاعديًا (ORDER BY) واختره ضمن الأعمدة. والتشغيل الفاشل لا يحرّك نقطة التوقف، فلا يضيع شيء؛ واحذف ملف الحالة لتبدأ من جديد.

{
  "Name": "new-orders",
  "Sql": "SELECT \"Id\", \"CustomerName\" FROM \"Orders\" WHERE \"Id\" > :lastKey ORDER BY \"Id\"",
  "KeyColumn": "Id", "KeyParameter": "lastKey", "KeyType": "Number", "InitialKey": "0"
}

Scheduling it

Task Scheduler → Create Task: an account that can reach the database and write the folder, Run whether user is logged on or not, your trigger, and the action C:\Tools\QueryRunner\Jadwal.QueryRunner.exe with the config path as its argument. Exit code 0 means success and 1 failure, shown as the task's Last Run Result.

جدولتها

Task Scheduler ← Create Task: حساب يصل إلى قاعدة البيانات ويكتب في المجلد، وRun whether user is logged on or not، والموعد الذي تريده، والإجراء C:\Tools\QueryRunner\Jadwal.QueryRunner.exe مع مسار ملف الإعداد وسيطًا. رمز الخروج 0 يعني النجاح و1 الفشل، ويظهر في Last Run Result.

The Word user manuals

docs/user-manual/Jadwal-User-Manual-EN.docx and -AR.docx are generated, not edited by hand. After a change to the screens, generate them again so the pictures and text match.

دليلا المستخدم بصيغة Word

الملفان docs/user-manual/Jadwal-User-Manual-AR.docx و-EN.docx يُولَّدان ولا يُعدَّلان يدويًا. وبعد أي تغيير في الشاشات، ولّدهما من جديد لتتطابق الصور والنصوص.

# 1. The business tables the examples read (reload when older than a few weeks: the order dates follow the load date)
sqlplus test/test@host/service @database/demo-data.sql        # with NLS_LANG=.AL32UTF8

# 2. Start the app
dotnet run --no-launch-profile --urls http://localhost:60187  # in src/Jadwal.API
npx ng serve --port 4200                                       # in client/

# 3. Build both manuals (from docs/user-manual)
npm install; python -m pip install python-docx                # first time only
npm run manual                                                 # seed + capture per language, then build

  • Seeding deletes Jadwal's own content (dashboards, tasks, reports, queries, groups) before creating the demo set. Never run it against a real installation. It never deletes user accounts.
  • The capture cannot change data. Every request other than GET is blocked except signing in and running a query, and password-like columns are masked before a picture is taken.
  • The demo content is seeded once per language, because the app does not translate what an administrator typed; the Arabic pass runs last.
  • Settings by environment variable: MANUAL_APP_URL, MANUAL_API_URL, MANUAL_LOCALES, MANUAL_THEME, MANUAL_OUT_DIR (use it when Word has the file open), and the account variables.
  • In Word, right-click the contents table and choose Update Field to fill in page numbers.
  • التهيئة تحذف محتوى «جدول» (اللوحات والمهام والتقارير والاستعلامات والمجموعات) قبل إنشاء المحتوى التجريبي. لا تشغّلها أبدًا على تثبيت حقيقي. ولا تحذف حسابات المستخدمين.
  • التصوير لا يستطيع تعديل البيانات. كل طلب غير GET ممنوع ما عدا تسجيل الدخول وتشغيل الاستعلام، وتُخفى الأعمدة الشبيهة بكلمات المرور قبل التصوير.
  • يُهيأ المحتوى التجريبي مرة لكل لغة، لأن التطبيق لا يترجم ما يكتبه المسؤول؛ والجولة العربية تعمل أخيرًا.
  • الإعدادات بمتغيرات البيئة: MANUAL_APP_URL وMANUAL_API_URL وMANUAL_LOCALES وMANUAL_THEME وMANUAL_OUT_DIR (استخدمه حين يكون الملف مفتوحًا في Word)، ومتغيرات الحسابات.
  • في Word، انقر بالزر الأيمن على جدول المحتويات واختر Update Field لتظهر أرقام الصفحات.
